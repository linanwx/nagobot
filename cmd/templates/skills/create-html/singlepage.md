# HTML single page (long-form layout)

Use when the user wants a self-contained web page that reads as a document — article, report, infographic, dashboard, presentation slide, landing page, weekly summary, status update.

The shared workflow (write → `nagobot upload-html` → share URL) and the inline-only critical rules live in the parent `SKILL.md`. This file covers layout, typography, and section patterns specific to long-form pages.

## Page anatomy

A typical singlepage has:

- A **header** with title, subtitle, date / author / context line.
- A series of **sections** (`<section>` with `<h2>` heading) — paragraphs, lists, tables, code blocks, or embedded SVG illustrations.
- An optional **table of contents** with `<a href="#section-id">` anchors when the page is long.
- A **footer** with source / generation timestamp / link to data.

Constrain reading width — long lines hurt readability. `max-width: 720–860px` for prose pages; up to `1200px` for dashboards / infographics.

## Layout primitives

- **Flexbox** for header/footer rows and side-by-side cards.
- **CSS Grid** for dashboard tiles, multi-column layouts, photo grids (`grid-template-columns: repeat(auto-fit, minmax(220px, 1fr))`).
- **`<details>` / `<summary>`** for collapsible deep dives without JS.
- **Inline SVG** for small charts or icons embedded inside the page (see `image.md` for SVG patterns).

Avoid JS unless absolutely needed. Most interactivity can be done in pure CSS — accordion via `<details>`, tabs via `:checked` + sibling selectors, hover reveals.

## HTML template

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Descriptive Title</title>
  <style>
    * { margin: 0; padding: 0; box-sizing: border-box; }
    body {
      font-family: system-ui, -apple-system, "Noto Sans SC", "PingFang SC", sans-serif;
      color: #0f172a; background: #fff;
      line-height: 1.6; padding: 32px 20px;
    }
    main { max-width: 820px; margin: 0 auto; }
    header { border-bottom: 1px solid #e2e8f0; padding-bottom: 1rem; margin-bottom: 2rem; }
    h1 { font-size: 2rem; font-weight: 700; margin-bottom: .5rem; }
    h2 { font-size: 1.5rem; font-weight: 600; margin: 2rem 0 .75rem; }
    h3 { font-size: 1.2rem; font-weight: 600; margin: 1.25rem 0 .5rem; }
    p { margin: .75rem 0; }
    ul, ol { padding-left: 1.5rem; }
    .meta { color: #64748b; font-size: .9rem; }
    .card { background: #f8fafc; border: 1px solid #e2e8f0; border-radius: 12px; padding: 1.25rem; margin: 1rem 0; }
    .grid { display: grid; grid-template-columns: repeat(auto-fit, minmax(220px, 1fr)); gap: 1rem; }
    code { background: #f1f5f9; padding: .1rem .35rem; border-radius: 4px; font-size: .9em; }
    pre { background: #f8fafc; border: 1px solid #e2e8f0; border-radius: 8px; padding: 1rem; overflow-x: auto; }
    a { color: #4f46e5; }
    table { width: 100%; border-collapse: collapse; margin: 1rem 0; }
    th, td { text-align: left; padding: .5rem .75rem; border-bottom: 1px solid #e2e8f0; }
    th { background: #f8fafc; font-weight: 600; }
    blockquote { border-left: 4px solid #4f46e5; padding: .5rem 1rem; color: #475569; background: #f8fafc; border-radius: 0 8px 8px 0; margin: 1rem 0; }
    footer { margin-top: 3rem; padding-top: 1rem; border-top: 1px solid #e2e8f0; color: #64748b; font-size: .85rem; }
  </style>
</head>
<body>
  <main>
    <header>
      <h1>Descriptive Title</h1>
      <p class="meta">Subtitle · 2026-05-04</p>
    </header>

    <section>
      <h2>Section heading</h2>
      <p>Body paragraph.</p>
    </section>

    <footer>Generated by nagobot · 2026-05-04</footer>
  </main>
</body>
</html>
```

## Common section patterns

### Stat card grid (dashboard / report)

```html
<section class="grid">
  <div class="card">
    <div class="meta">Active users</div>
    <div style="font-size:1.75rem;font-weight:700;">12,430</div>
    <div class="meta" style="color:#22c55e;">+8.2% vs last week</div>
  </div>
  <div class="card">…</div>
</section>
```

### Embedded SVG illustration inside the page

```html
<section>
  <h2>Architecture</h2>
  <svg viewBox="0 0 800 300" xmlns="http://www.w3.org/2000/svg" style="width:100%;height:auto;">
    <!-- inline SVG — see image.md for SVG patterns -->
  </svg>
</section>
```

### Collapsible details (no JS)

```html
<details>
  <summary>Why this matters</summary>
  <p>Hidden by default; click to expand.</p>
</details>
```

### Quote / callout

```html
<blockquote>Pull quote or callout text.</blockquote>
```

### Two-column responsive layout

```html
<section style="display:grid; grid-template-columns: 1fr 1fr; gap: 1.5rem;">
  <div>Left column.</div>
  <div>Right column.</div>
</section>
```

On narrow screens this collapses naturally if you switch to `grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));`.

## Trigger conditions

- Article, blog post, weekly digest, status update, retro write-up.
- Report (sales, growth, postmortem, incident review).
- Infographic — text + small embedded charts as one cohesive page.
- Dashboard summary with stat cards.
- Presentation slide / one-pager pitch.
- Landing page / launch announcement.

## When to switch to `image.md`

If the deliverable is a single graphic with no reading flow (just a chart, just a flowchart, just a system diagram), wrapping a lone SVG in a long-form page wastes layout work — use `image.md` instead.
